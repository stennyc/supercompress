> 仓：stennyc/supercompress（sc 侧 + engine 壳 + tests，宿主 agent/ 零 diff——owner 红线 1）。
> 现有水线（PRD 取代面）：① 55% compact 触发（DISTILL_WATER_FRAC）② 80% P2/P1 软逐（water）③ 15% P0 push cap（PUSH_CAP_FRAC）④ 75% R3 逃生门（force_ratio）⑤ §4.5 90% P0 段级折存根（p0_90pct_water，working tree 未 commit）⑥ 100% force_evict 兜底。

## 0. 两条独立失败面（owner 反复强调，不可混）

| 面 | 位置 | 治法 | 本 PRD 覆盖 |
|---|---|---|---|
| **A. sc 窗口膨胀**（sc store replay `w.used_tokens` 1.28M > cap 512k） | `sc/distill.py` run() 逐出链 + `engine._window_fresh()` | 降档水位递进带（90→75→65→55）让 sc 窗口降到 cap 下 | ✅ 主体 |

**关键判定（第四轮 reviewer/data-manager 活数据钉死）**：宿主 `session_db` messages 是宿主独立一份（`_flush_messages_to_session_db` 宿主独立 flush），sc 逐出 sc store 段**不直接回写**宿主 live 行；但宿主 compact commit 走 `archive_and_compact`（宿主把 sc 输出写回 session_db live 行），**sc 输出（rough_out）比宿主 live 行（rough_in）小 → refuse 放行 → commit → 宿主 live 行缩短**。所以 B 面的破法 = **让 sc 输出 < 宿主 live 行**（sc 侧做，不碰宿主 refuse 闸代码、不越红线 1，代价 = 破 owner 10-14 铁律 4"旧账本页字节冻结换前缀缓存命中"——owner 10-17 已拍板接受）。

## 1. 降档水位递进带（A 面主体）

### 1.1 执行序（降档，非升档——owner 纠正）

compact 触发（sc 侧 55% 预检）后，**从最高危险度档先试、逐档降**，每档"压到目标水位下就停、压不到（估值回收不足）pass 给下一档"：

```
used_tokens > 0.9×cap  → ① 90% 逃生门（B 面叠省）：逐最前账本页 c#N 折存根 + P0 段退窗口 digest_only
                          压到 0.9×cap 下 → 停；压不到 → pass 给 ②
used_tokens > 0.75×cap → ② 75% 折存根：先折 P1/P2 存根、不足才折 P0 存根
                          压到 0.75×cap 下 → 停；压不到 → pass 给 ③
used_tokens > 0.65×cap → ③ 65% compact 分页：开 c#N 新页 + 退最旧 P0/P1 段
                          压到 0.65×cap 下 → 停；压不到 → pass 给 ④
used_tokens > 0.55×cap → ④ 55% 清垃圾：drift 旧 epoch P1/P2 + egress（room-skeleton/agent 自述）
                          常态兜底面（最便宜、可逆）
```

**与现状的本质差别**：现状是"55% 一触发全链跑（80% 软逐 + push cap + §4.5 90% 段级）"、无分档、无估值 gate、无"压到目标下就停"。本 PRD 把 80% 软逐（②里的 P2/P1 逐到 0.8×cap）并入 75% 档、把 §4.5 90% 段级升级为 90% 账本页级逃生门、新增 65% 分页档 + 55% 清垃圾兜底档、每档带估值 gate。

### 1.2 估值 gate（分母 = 当前用量 `w.used_tokens`，owner 裁定）

每档"压到目标水位下"前，先用**代码层确定性估值**估算该档动作能省多少；省量 < 阈值 → 不执行该档、pass 给下一档（省 LLM 面开销、避免无效 compact）。

| 档 | 估值分子（代码层怎么算） | 阈值 | 可确定性算？ |
|---|---|---|---|
| ① 90% 逃生门 | Σ(被逐最前账本页 c#N 全文 est_tokens − 存根 est_tokens) + Σ(退窗口 P0 段 est_tokens(原文) − est_tokens(digest 摘录)) | 省 ≥ 15%×used | ✅ 确定性（est_tokens 纯函数） |
| ② 75% 折存根 | Σ(P1/P2 段 est_tokens(原文) − 存根) （不足才 + P0 段同上） | 省 ≥ 20%×used | ✅ 确定性 |
| ③ 65% compact 分页 | 开新页 c#N 省 = 退最旧 P0/P1 段省（同上估）；LLM 出块缩 middle **不估**（出块前不可知，执行后回算） | 省 ≥ 20%×used | ⚠️ 半确定（只估退段省、不估 LLM 出块省 → 系统性偏保守，估不足才 pass 给 55%，不漏做） |
| ④ 55% 清垃圾 | drift.hard_evict 旧 epoch P1/P2 省 + egress 过滤省 | 省 ≥ 15%×used | ✅ 确定性（drift 纯函数、egress 谓词） |

**分母口径（owner 拍）**：`w.used_tokens`（sc 窗口当前全段 resident+digest 摘录累加，`distill.py:60`）。阈值 15%/20%/20% 都是"省量 / 当前用量"。

**65% 档估值降级（关键设计）**：65% compact 的真实回收含 LLM 出块（不可代码层估），**65% 档 gate 只用"退最旧 P0/P1 段省"做估值（偏保守），估不足就 pass 给 55% 兜底**——不会因 LLM 出块面估不准导致恒不 compact 顶死（这是降档序比升档序干净的核心：65% 是第 3 手、90/75 确定性估值已压到位就绕开 LLM 面，65% 估不准只 pass 给 55%、不决定救命）。

### 1.3 "全 pass 不落地"风险（reviewer 面 1 钉死）

降档序每档"压不到 → pass 下一档"是**单调累积**（档 i 做完的折存根/退段保留到档 i+1，回收量单调不降）。最末手 55% 清垃圾做完全链累计回收最大；若 55% 也压不到 0.55×cap 下 ⇒ 窗口内已无可操作面 ⇒ 物理满（backpressure 正解，`result.status="backpressure"`，宿主 force_evict 兜底接）。**无死循环、无顶死**（升档序里 55% 先试的"弱手段先磨"在降档序里反转：危险第一手 = 最强手段）。

### 1.4 55% 不清带入 65% 的无害性（owner 上一轮问的）

55% 的"不清"（估值 < 15% 不清 / 该清但清不动）= 窗口原样保留、垃圾没锁死没丢失，65% 看到的是完整窗口、按段自身 tier/epoch 标记接着处理（`drift.hard_evict` 筛旧 epoch P1/P2、`is_old_epoch` 判 session_topic，与 55% 是否清过正交）。**无负面影响**；唯一代价是 65% 负载更大（进 65% 时窗口更大），由 65% 自身估值 gate 兜底（扛不动 pass 给 55%）。

## 2. 90% 逃生门两面叠省（B 面，owner 选 (b)）

### 2.1 两面（owner 第三轮叫的"两面叠省"）

90% 超压（`used_tokens > 0.9×cap`）触发时，**同一档内两个回收面叠一起**：

1. **A 面（降 sc 窗口 `w.used_tokens`）**：P0 段退窗口 `form=resident → digest_only`（`WindowSeg.tokens()` 口径 `distill.py:42-45`：resident 算 `est_tokens(original_text)` 全文、digest_only 算 `est_tokens(digest 摘录)`）→ sc 窗口 1.28M 掉到 cap 下。结构 P0（goal/ledger 尾，`kind in ("goal","ledger")`）**永不退**（结构地板，`_next_candidate` L235/L238）；user 指令 P0（kind=segment）90% 超压可退。
2. **B 面（降宿主 refuse 分子 `rough_out`）**：把**宿主全量重注入面**裁成存根——
   - **(b-1) 宿主 live 行的 P0 全量原文**：sc compress 输出（`out`）里 head(3)+尾(6) 保护区的 P0 段若为 resident 原文（超长 P0 指令 232K 那种），**90% 超压时折成存根行**（durable 锚点 segment_id 可定位、原文 sc store 已沉盘可 recall），让 `rough_out` 里这些段从全文降成存根。
   - **(b-2) 账本旧页全文（铁律 4 破面）**：90% 超压时**旧账本页 c#1..c#N（settled=False 的全文页）也折存根进注入面**（`evict_page` 折到旧页，不只折当前页）——`ledger.text()` 变短 → sc 输出（`rough_out`）变小。**这是破 owner 10-14 铁律 4（旧页字节冻结换前缀缓存命中）的代价面，owner 10-17 已拍板接受**：90% 超压时前缀缓存从"旧页全命中"降级为"被逐出页位置起回落"（N 次可控 flush，不破 append-only 单调，只是 flush 位变多）。

**两面叠省后**：`rough_out`（sc 输出 = head 存根 + 账本存根 + 尾存根）< `rough_in`（宿主 live 行原文）→ 宿主 refuse 闸（`_rough_out > _rough_in`）放行 → commit → 宿主 live 行缩短 → 474k context_overflow 400 消除。**全程 sc 侧，宿主 refuse 闸代码零改（不越红线 1）。**

### 2.2 与现状 §4.5 的关系（叠加取代，非并存）

现状 §4.5（`distill.py:111/178-182`，working tree 未 commit）= 90% 段级 P0 折存根（`_evict_until(w, 0.9×cap, tiers=("P0",))` 逐 P0 段翻 digest_only + `ledger_evict_cb` 折活账本当前页存根）。**本 PRD 的 90% 面 = §4.5 的账本页级升级 + B 面存根裁剪**：
- 保留 §4.5 的"P0 段退窗口 digest_only"（A 面，`_next_candidate` 放开 user 指令 P0、goal/ledger 尾永不逐、digest 未 ready 走 head80 占位——这些语义不变）；
- **新增 B 面**（宿主 live 行 P0 原文折存根 + 账本旧页折存根进注入面）——这是 owner 选 (b) 的破 474k 路径；
- §4.5 的 699 tests 锚（`test_p0_90pct_force.py` F1-F6）在 B 面落地时**同步更新**（F3/F4 结构 P0 90% 放开语义保留、新增 B 面存根裁剪断言）。

### 2.3 前缀缓存面（铁律 4 破面，owner 已接受）

90% 逃生门 B 面（账本旧页折存根 + 宿主 live 行 P0 折存根）**破 owner 10-14 铁律 4**：
- 现状铁律 4：旧账本页字节冻结 → provider 前缀缓存跨 compact 命中除最后一页外全部旧页（`test_ledger_paging.py` T8/T9 锁死）。
- 90% B 面后：被逐出账本页 + 被折存根的 P0 段原文退场 = **该位置起前缀缓存断裂一次**（N 页被逐 = N 次可控 flush），旧更早未逐页字节仍冻结（append-only 单调不破，只是 flush 位变多）。
- **80-90% 区间零变化**（`used_tokens ≤ 0.9×cap` 时 90% 面不触发、铁律 4 旧页冻结不变）——只有真超压到 90% 才破前缀，代价有界。
- owner 接受此取舍（10-17 拍板选 b）：**宁可 90% 超压时前缀缓存回落，也要破 474k refuse 卡死**（refuse 拒 = 会话彻底死，前缀缓存回落 = 多付一次 re-prime 成本，远小于死锁）。
